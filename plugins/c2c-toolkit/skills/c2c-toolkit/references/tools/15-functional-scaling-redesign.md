# FUNCTIONAL SCALING REDESIGN TEMPLATE
Author: Eric Weiss  
Purpose: Systematic Redesign of Individual Business Functions  
Audience: CEOs, Functional Leaders, Executive Teams  

---

# 1. PURPOSE OF THIS FRAMEWORK

When growth slows, leaders assume:

- We need more people.
- We need better talent.
- We need more effort.

In most cases, the function is structurally fragile.

This template forces:

- Bottleneck identification
- Interface clarity
- Authority redesign
- Automation assessment
- Accountability enforcement

It is applied to one function at a time.

Do not redesign the entire company simultaneously.

---

# 2. WHEN TO USE THIS

Use when:

- A specific function is underperforming
- Growth is plateauing
- Cross-team friction increases
- KPIs are inconsistent
- Founder is intervening frequently
- Team morale is declining

Pick the most constrained function first.

---

# 3. STEP 1 — DEFINE CURRENT STATE

For the selected function:

## Function Name

## Accountable Owner
Single person.

## Current KPIs
List 3–5 measurable metrics.

## Current Performance Reality
- Trend direction
- Volatility
- Visibility lag

## Founder Involvement Level
- High
- Medium
- Low

Be honest.

---

# 4. STEP 2 — IDENTIFY PRIMARY CONSTRAINT

Ask:

- Where does work queue?
- Where are decisions delayed?
- Where are errors frequent?
- Where is rework common?
- Where is morale lowest?
- What creates the most escalation?

Classify constraint:

- Demand constraint
- Capacity constraint
- Authority constraint
- Process constraint
- Skill constraint
- Tool constraint

Select one primary constraint.

---

# 5. STEP 3 — HUMAN BOTTLENECK ANALYSIS

Identify:

- Who must approve most decisions?
- Who holds critical knowledge?
- Who feels overloaded?
- Where does context accumulate?

Then ask:

If this person disappeared for 30 days,
what would break?

If answer is “everything,”
system is fragile.

---

# 6. STEP 4 — INTERFACE REDESIGN

Map:

- Upstream inputs
- Downstream outputs
- Cross-functional dependencies

For each interface define:

- What is delivered
- In what format
- On what cadence
- With what SLA
- Escalation protocol

Undefined interfaces create friction.

---

# 7. STEP 5 — AUTHORITY REDISTRIBUTION

Clarify:

- What decisions remain centralized?
- What decisions can move down?
- What thresholds define escalation?
- What decisions require cross-functional input?

Use decision matrix:

| Decision Type | Owner | Consultation | Escalation Rule |

Remove invisible veto power.

---

# 8. STEP 6 — AUTOMATION & TOOLING LAYER

Ask:

- What manual process can be templated?
- What repetitive task can be automated?
- What reporting can be system-generated?
- What visibility can be dashboarded?

Automation reduces cognitive load.

Avoid tool sprawl.
System design first, tools second.

---

# 9. STEP 7 — KPI VISIBILITY UPGRADE

For each KPI ensure:

- Weekly visibility
- Leading indicators identified
- Clear owner
- Defined acceptable range
- Trigger thresholds defined

If KPI reviewed monthly only,
too slow for growth stage.

---

# 10. STEP 8 — CAPACITY BEFORE DEMAND CHECK

Ask:

- What breaks at 2x volume?
- What is already fragile?
- What relies on heroics?
- What would collapse under sudden spike?

Build structural capacity before pushing demand.

---

# 11. STEP 9 — IMPLEMENTATION PLAN

Redesign must be phased.

Week 1:
Clarify authority + bottleneck removal.

Week 2:
Interface documentation.

Week 3:
Automation upgrades.

Week 4:
KPI dashboard refinement.

Avoid big-bang reorgs.

---

# 12. FAILURE MODES

AI must guard against:

- Hiring before redesign
- Blaming individuals
- Overcomplicating process
- Ignoring authority clarity
- Treating culture as fix
- Expanding scope beyond one function

Focus creates leverage.

---

# 13. MATURITY SCORE AFTER REDESIGN

Rate 1–5:

| Dimension | 1 = Fragile | 5 = Scalable |
|------------|-------------|--------------|
| Bottleneck clarity |
| Authority clarity |
| Interface clarity |
| KPI visibility |
| Automation level |
| Founder dependency |

If any category below 3,
redesign incomplete.

---

# 14. AI IMPLEMENTATION RULES

If another AI applies this template:

It must:

1. Isolate one function only.
2. Demand single accountable owner.
3. Identify one primary constraint.
4. Surface human bottleneck explicitly.
5. Redesign authority.
6. Clarify interfaces.
7. Upgrade KPI cadence.
8. Phase implementation.
9. End with one immediate structural action.

Tone:

- Analytical
- Calm
- Direct
- Systems-focused
- Execution-oriented

Never:

- Recommend hiring first.
- Allow shared ownership.
- Ignore founder involvement.
- Skip automation layer.
- Allow vague improvement plans.
