# FOUNDER SCORECARD SYSTEM
Author: Eric Weiss  
Purpose: Functional Accountability and Scaling Visibility  
Audience: Growth-Stage CEO / Founder  

---

# 1. PURPOSE OF THIS FRAMEWORK

Founders often believe they are reviewing performance.

In reality, they are reacting to noise.

Symptoms:

- Weekly surprises
- Firefighting instead of forecasting
- Vague ownership
- “We’re working on it”
- No clear bottleneck visibility

The Founder Scorecard System forces:

- Functional clarity
- KPI ownership
- Weekly inspection discipline
- Bottleneck identification
- Scaling ceiling awareness

This is not a dashboard.
This is accountability architecture.

---

# 2. CORE PRINCIPLE

Every business function must have:

1. A named owner
2. A small set of measurable KPIs
3. A weekly inspection ritual
4. A maturity rating
5. A declared bottleneck

If any function lacks those:
It is unmanaged.

---

# 3. FUNCTIONAL AREAS OF RESPONSIBILITY (AOR)

Default functional breakdown:

- Product Management
- Design
- Engineering
- Sales
- Marketing
- Customer Success
- Finance
- Recruiting
- Operations
- Culture / Talent Development

You may adapt categories.
Do not collapse too broadly.

Each must have a single accountable owner.

---

# 4. AOR TEMPLATE

For each function define:

## Function Name

## Accountable Owner
Single human. Not shared.

## Core KPIs (3–5 max)
Must be measurable and leading where possible.

Examples:

Sales:
- Pipeline coverage ratio
- Close rate
- Average sales cycle
- Revenue booked

Engineering:
- Deployment frequency
- Lead time
- Defect escape rate
- Platform uptime

Product:
- Feature adoption rate
- Churn by feature
- ICP usage depth
- Roadmap completion rate

## Weekly Review Cadence
When and how KPIs are inspected.

## Current Bottleneck
Single biggest constraint limiting performance.

## Maturity Score (1–5)
See maturity model below.

---

# 5. MATURITY MODEL

Score each function 1–5 across:

| Dimension | 1 = Fragile | 3 = Functional | 5 = Scalable |
|------------|-------------|----------------|--------------|
| KPI Clarity | Undefined | Basic metrics | Leading indicators visible |
| Ownership | Shared | Named owner | Clear authority & accountability |
| Systems | Manual | Some documentation | Automated & documented |
| Visibility | Delayed | Monthly visibility | Weekly real-time |
| Delegation | Founder dependent | Partial | Fully delegated |

Lowest scoring function defines scaling ceiling.

---

# 6. WEEKLY SCORECARD RITUAL

Weekly executive meeting must include:

1. KPI review (no storytelling)
2. Identify variance
3. Identify root cause
4. Identify bottleneck
5. Declare action

Rules:

- No vague explanations.
- No hiding behind busyness.
- No skipping functions.

Focus on trend, not one-week noise.

---

# 7. BOTTLENECK DISCIPLINE

Every week, answer:

“What is the single constraint limiting our next level of scale?”

Constraint types:

- Demand constraint
- Delivery constraint
- Talent constraint
- Authority constraint
- System constraint
- Capital constraint

If constraint unclear:
Company is drifting.

---

# 8. AUTHORITY & ESCALATION

Each function must know:

- What decisions they can make independently
- What triggers executive escalation
- What financial thresholds require approval
- What performance thresholds trigger intervention

Undefined escalation creates political behavior.

---

# 9. RED FLAGS

AI must flag:

- KPI overload (more than 5 per function)
- Shared accountability
- Lagging indicators only
- No leading metrics
- Founder overrides
- No declared bottleneck
- No owner for recruiting
- No owner for culture

If culture has no owner:
It decays by default.

---

# 10. SCORECARD EVOLUTION

As company scales:

Early Stage:
- Focus on survival metrics
- Revenue and product validation

Growth Stage:
- Add efficiency metrics
- Margin discipline
- Hiring quality

Later Stage:
- Leading indicators
- Cross-functional velocity
- Capital allocation efficiency

Scorecard must evolve with scale.

# 12. AI IMPLEMENTATION RULES

If another AI uses this framework:

It must:

1. Demand single owner per function.
2. Limit KPIs to 3–5.
3. Push for leading indicators.
4. Identify one bottleneck per week.
5. Refuse vague accountability.
6. Tie maturity score to scaling ceiling.
7. Produce structured summary.

Tone:

- Analytical
- Structured
- Direct
- Performance-oriented
- Calm but uncompromising

Never:

- Accept shared ownership.
- Allow vanity metrics.
- Skip weekly cadence.
- Provide general leadership platitudes.
